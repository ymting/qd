# 模板变更记录

本文件记录 `templates/` 下 HAR 模板的对外行为变更。版本号规则为 `YYYYMMDD.N`，
与项目发布版本同构；每次影响签到行为或必需变量的修改都要升版本并在此登记。

维护方式：

```bash
python tools/template_manifest.py --check                 # 校验清单与模板一致
python tools/template_manifest.py --set-version <文件> <版本号>   # 升版本并记录日期
python tools/template_manifest.py --write                 # 重新计算 sha256/条目数/任务变量
```

> **重要**：QD 数据库里保存的是导入当时的 HAR 快照。仓库模板更新后必须重新导入，
> 旧任务不会自动同步。每个模板的末步日志都会输出 `v<版本号>`，
> 可在推送消息中确认任务实际运行的模板版本。

## 20260915.1 - 2026.09.15

### Added

1. 全部模板的签到日志新增版本号输出，例如 `（模板 v20260915.1）`；
   日志中看不到版本号即说明该任务仍在运行旧模板。
2. 新增 `templates/manifest.json` 与 `tools/template_manifest.py`，
   把版本号、SHA-256、条目数、任务变量和外层镜像状态纳入可机检的清单。

### Fixed

1. 吾爱破解：领取奖励步骤不再直接用正文判定结果，改为「HTTP 200 + 登录有效」，
   未取得明确成功提示时访问 `home.php?mod=task&do=view&id=2` 复核任务真实状态。
   网站返回「不是进行中的任务」时，若详情页显示本期已完成则判定今日已签到，
   不再误报失败；详情页显示可立即申请时仍按失败处理。
2. 吾爱破解：全部对外请求补充传输层失败分类。QD 会把 `curl_cffi` 异常合成为
   HTTP 599（curl 28 连接超时），原模板只报「响应不是200」，无法判断是网络问题还是站点问题。
   现在会明确提示检查出口网络并建议提高 `REQUEST_TIMEOUT` / `CONNECT_TIMEOUT`。

### Migration

1. 所有模板都需要重新导入；未重新导入的任务不会出现版本号，可据此识别。
2. 吾爱破解模板条目数由 23 变为 28（新增复核分支与分支标记行）。

## 继承历史（未编号版本）

以下改动发生在引入版本号之前，按项目记忆汇总，便于对照旧模板：

- 吾爱破解：修复首次 `do=apply&id=2` 返回 302 导致任务中止；新增有界同站跳转校验、
  `dynamicurl` 变量清理、明确的完成/已签到判定与积分缺失回退。
- 吾爱破解：增强领取奖励步骤的失败分类（非 200、要求登录、非进行中任务）。
- 烧饼论坛：新增 `login_mode` 本地校验，非法模式在发起任何请求前失败；
  修正常登录页关键词误命中「Cloudflare」用户名导致的误报。
- NovaAI / Haokun：适配 New API `v1.0.0-rc.22` 的 Bearer access token 认证。
- NovaAI：按 `checked_in_today` 跳过重复签到请求，避免幂等响应被误判为失败。
- NodeSeek / DeepFlood：浏览器指纹默认值改为 `chrome` + `auto`，变量名统一为纯英文。
